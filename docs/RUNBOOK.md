# Как запускать и разбирать тесты

## Первый запуск на macOS

1. Откройте Finder → `Documents` → `social-frontend-e2e`.
2. Откройте папку в VS Code: File → Open Folder.
3. В VS Code выберите Terminal → New Terminal.
4. Выполните `pwd` и убедитесь, что получили `/Users/stanislav/Documents/social-frontend-e2e`.
5. Проверьте Node.js: `node --version`. Нужна версия 20 или 22.
6. Установите зависимости: `npm install`.
7. Установите браузеры: `npx playwright install chromium webkit`.
8. Создайте `.env` из примера: `cp .env.example .env`.
9. Откройте `.env`, укажите `E2E_EMAIL` и `E2E_PASSWORD`. Никому не отправляйте этот файл.
10. Проверьте TypeScript: `npm run typecheck`.

## Безопасный ежедневный запуск

1. В терминале проекта выполните `npm test`.
2. Дождитесь итоговой строки. `passed` — успешные тесты; `failed` — неожиданные падения.
3. `Expected to fail, but passed` означает, что известный дефект исправлен и метку `test.fail` пора удалить.
4. Откройте HTML-отчёт: `npm run report`.
5. В отчёте нажмите на упавший тест и изучите шаг, screenshot, video, trace и `network.json`.

## Запуски по назначению

| Задача | Команда |
|---|---|
| Быстрый smoke | `npm run test:smoke` |
| Все безопасные | `npm test` |
| Только desktop | `npm run test:desktop` |
| Mobile Chromium | `npm run test:mobile` |
| Диагностические интеграционные проверки | `npm run test:integration` |
| Основные E2E без диагностических | `npm run test:e2e` |
| Браузер видим | `npm run test:headed` |
| Интерактивный UI | `npm run test:ui` |
| Пошаговый debug | `npm run test:debug` |

## CRUD-тесты

CRUD меняет dev-данные, поэтому запускайте его осознанно:

1. Убедитесь, что используете тестового пользователя и dev-стенд.
2. Закройте другие параллельные прогоны этого пользователя.
3. Выполните `npm run test:mutation`.
4. Тесты создадут сущности с префиксом `QA-E2E-` и удалят их в `finally` через UI.
5. Если процесс был принудительно остановлен, найдите оставшиеся сущности по `QA-E2E-` и удалите их вручную.
6. Полный прогон безопасных и CRUD-тестов: `npm run test:all`.

## Как анализировать падение

1. Сначала прочитайте ошибку ожидания: что ожидалось и что получено.
2. Посмотрите screenshot — правильная ли страница открыта.
3. Посмотрите video — не перекрыл ли элемент баннер или модальное окно.
4. Откройте trace указанной в ошибке командой `npx playwright show-trace <путь-к-trace.zip>`.
5. На вкладке Network проверьте статус запроса; безопасная копия выбранных ответов приложена как `network.json`.
6. Повторите только один тест: `npx playwright test путь/к/spec.ts -g "часть названия"`.
7. Не добавляйте произвольные паузы. Ожидайте наблюдаемое состояние через `expect`.
8. Если дефект подтверждён вручную и автотестом, оформите его по шаблону из `docs/BUGS.md`.
