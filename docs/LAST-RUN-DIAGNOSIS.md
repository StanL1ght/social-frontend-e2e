# Разбор запуска: 2 прошли, 2 упали, 39 пропущены

Проверен сохранённый HTML-отчёт в Documents/social-frontend-e2e: 43 проверки, 2 expected, 2 unexpected, 39 skipped.

Обе ошибки: `Error reading storage state from .auth/user.json: ENOENT: no such file or directory`.

- `setup / authenticate` пытается прочитать сессию прежде, чем создаст её. Общий `use.storageState` задаёт файл; `undefined` в setup не отменил наследование в этом запуске.
- Тест двух пользователей создаёт контексты без явного пустого storageState, и они также пытаются прочитать отсутствующий файл.
- 39 проверок зависят от setup и не запускаются после его падения.
- Две независимые проверки формы входа прошли.

Исправление внесено: по умолчанию контексты используют `storageState: { cookies: [], origins: [] }`. Файл сессии указан только для desktop/mobile-проектов, зависящих от setup. Контексты администратора и участника явно начинают с пустой сессии. Создавать фиктивный user.json вручную не нужно. Подготовка авторизации успешно прошла отдельно и в составе безопасного набора.

Проверка типов проходит. Набор выполняется одним worker. LoginPage ожидает появления формы входа или готовой ленты вместо мгновенной проверки URL. Исправления находятся в копии Documents; копия Projects в этом исправлении не изменялась.

Fixture теперь проверяет вход перед каждым сценарием и обрабатывает повторный запрос пароля от SSO. Поле логина заполняется только при наличии, по доступному имени «Email или телефон».

Финальная проверка: `npx playwright test tests/smoke/navigation.spec.ts tests/mobile/mobile-layout.spec.ts --grep 'корневой маршрут|ширина страницы' --repeat-each=2` — 7 passed (setup и по два запуска в desktop Chromium, mobile Chromium, mobile WebKit). TypeScript проходит. Это проверка исправления авторизации, а не подтверждение успешности всех бизнес-сценариев. Предварительный полный безопасный прогон был остановлен для исправления повторного входа; в нём также обнаружены отдельные ошибки локаторов и перекрытие элементов баннером.

## Как понять причину по отчёту

1. Откройте терминал в `/Users/stanislav/Documents/social-frontend-e2e`.
2. Выполните `npm run report`.
3. Выберите Failed → `authenticate` → текст ошибки (Errors).
4. `ENOENT` означает отсутствие файла; рядом указан `.auth/user.json`.
5. Откройте второй упавший тест: причина та же, точка ошибки — `browser.newContext`.
6. В `playwright.config.ts` найдите `dependencies: ['setup']`: это объясняет пропуск зависимых тестов. Само число skipped причины не раскрывает.
7. При ошибке создания контекста screenshot может отсутствовать: браузер ещё не готов. Начинайте с текста ошибки.

Есть две разные копии: Documents и Projects. У каждой свои настройки и отчёты. Команда report открывает отчёт текущей папки; очередной запуск обычно заменяет предыдущий.

| Команда | Выбор тестов |
|---|---|
| `npm test` | Без @mutation |
| `npm run test:mutation` | Только @mutation и необходимая подготовка входа |
| `npm run test:all` | Все настроенные проекты, включая @mutation |

`test:all` уже есть в package.json обеих копий. Условия test.skip, например отсутствие данных второго пользователя, продолжают действовать и при полном запуске.

Вывод о подтверждённом дефекте мобильного поиска отозван по уточнению пользователя. Необоснованная проверка удалена из обеих копий. Старые отчёты сохраняют прежние названия.
